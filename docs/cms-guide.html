Quick start

  1. Get an invite. An administrator opens Admin > Users, clicks Invite User and picks your role. The link works once and expires after 7 days.
  2. Create your passkey. Open the invite link. Your device asks for Windows Hello, Touch ID or your phone. There is no password to remember.
  3. Sign in. Go to the admin link above and click Sign in with Passkey. Use the same browser address every time, because a passkey only works at the address where you created it.
  4. Find the right screen. Use the left sidebar. The table in Where is it edited? says which screen controls which part of the site.
  5. Change, save, check. Edit the field and click Save (or Publish on services and posts). Changes go live straight away. There is no rebuild and nothing to deploy. Open the page in another tab to check.

Tip: Add a second passkey (for example your phone) from your profile in the admin. If you lose one device, you can still sign in.

How-tos

Drafts and history depend on the screen. Services and Journal posts have drafts, Preview and a version history. Journal posts can also be scheduled. Pages, Team, Reviews and Site settings save straight to the live site and keep no history. Copy the old text into a note before a big rewrite.

Edit a page

  1. Open Pages in the sidebar and pick the page, for example About page.
  2. Open its single entry.
  3. Change the fields you need. Field names tell you where the text sits, for example H2 heading (our story).
  4. Click Save. The page is live at once.
  5. Open the page on the site and hard refresh (Ctrl + Shift + R, or Cmd + Shift + R on a Mac).

Leaving an optional field empty brings back the default wording. It does not break the page.

Write and schedule a blog post

  1. Open Journal (blog posts) and create a new entry.
  2. Type the H1 heading (post title). The slug (the web address) fills in from it. Shorten it if it is long.
  3. Write an Excerpt (up to 220 characters). It shows on the journal list and in search results when there is no meta description.
  4. Pick the Author and the Category. Add tags if the editor shows a Tags box. New
  5. Add a Featured image and fill in its alt text.
  6. Write the article in Post content. Use headings from H2 down, because the title is already the H1. Bold, links, lists and inline images all work.
  7. For internal links, type the path only, for example /services/kids/. Do not add /linden-dental. The site adds it on staging.
  8. Fill in the SEO panel (see the SEO checklist).
  9. Save as a draft and click Preview to read it as a visitor would.
  10. To publish now, click Publish. To publish later, use Schedule publication, pick the date and time, and confirm. Scheduled posts show in the Calendar.

Read time is worked out from the length. Drafts never appear on the real site, in the sitemap or in the RSS feed. On staging, drafts do show in the journal list with a draft notice, so the team can review them.

Replace a photo

  1. Open the entry that holds the photo (see the table above). For example, the home hero photo is Image (hero) on Pages > Home page.
  2. Click the image field. Choose a photo from the media library or upload a new one.
  3. Write the alt text: what the photo shows, in one plain sentence. Example: "Dr. Whitlock showing a young patient a model of teeth."
  4. Save (or Publish on services and posts).

To fix a photo everywhere it is used, open Content > Media, pick the photo and edit its Alt Text or focal point. The focal point decides which part stays visible when the photo is cropped.

Use JPEG or WebP. About 2000 px on the long side is plenty. Only upload photos the practice has the rights to.

Add a service

  1. Open Services and create a new entry.
  2. Fill in H1 heading (service name) and check the slug. The page will live at /services/your-slug/.
  3. Write the Excerpt. It is the text on the service card.
  4. Set Menu order. Lower numbers show first.
  5. Pick an Icon from the list.
  6. Add the Featured image with alt text, the Price and the Appointment length.
  7. Add at least one entry under Steps and any FAQs. FAQs also feed Google's FAQ data.
  8. Write the Page content, fill in the SEO panel, preview, then Publish.

The new service appears on /services/, in the home page list and in the sitemap by itself. It is not added to the header menu.

Change the header or footer links

  1. Open Manage > Menus.
  2. Pick Header menu or Footer menu.
  3. Add, rename, reorder or remove items. For a page on this site, type the path only, for example /about/. For another site, paste the full address starting with https://.
  4. Save. The new links show on every page at once.

The "Book a visit" button is not a menu item. Change it in Site settings and SEO (Button text and Button link: book a visit).

Add a redirect

Add one whenever you change the slug of a published service or post, or remove a page. Otherwise old links and Google results lead to a 404. Administrators only.

  1. Open Manage > Redirects and click New Redirect.
  2. Source path: the old path, for example /journal/old-post-name/.
  3. Destination path: the new path. On staging, start it with /linden-dental, for example /linden-dental/journal/new-post-name/. On the real domain later, leave that part out.
  4. Keep it permanent (301) unless the move is short-term. Use "Gone (410)" for a page that is removed for good with no replacement.
  5. Save, then test the old link in a private window.

The Redirects screen also lists 404 errors that visitors hit. Check it once a month and redirect the real ones.

Restore an old version

Works on Services and Journal posts.

  1. Open the entry and find Revisions.
  2. Pick the version you want. Use compare to see what changed.
  3. Click Restore. That version becomes your draft. The live page does not change yet.
  4. Check it, then click Publish.

Deleted entries go to the trash first and can be restored from there.

Preview a draft

  1. Save your changes as a draft. Do not publish.
  2. Click Preview in the entry editor. A preview of the page opens with your draft in place.
  3. Read it on desktop and phone width. Go back and edit if needed.
  4. Publish when it is right.

Visitors keep seeing the published version until you publish.

Edit text and photos on the page itself

  1. Sign in to the admin.
  2. In the same browser, open any page of the site. A black EmDash toolbar appears at the bottom.
  3. Turn on Edit mode in the toolbar.
  4. Click any heading or paragraph and type. It saves when you click away. The toolbar shows "Saved".
  5. Click a photo to replace it or change its alt text.
  6. Click an article body to open a rich editor in place.
  7. Lists (FAQs, steps, opening hours, principles, dropdown options) open that field in the admin instead.
  8. On services and posts, your edits wait as a draft. The toolbar shows "Unpublished changes" and a Publish button. Click it to go live. On the fixed pages, edits are live once saved.
  9. Turn Edit mode off when you are done.

Moderate comments New

  1. Open Manage > Comments. A number on the menu item shows how many are waiting.
  2. Read each one. Approve it, mark it as spam, or leave it pending.
  3. Delete anything that shares medical details about a named patient.

Comments from people signed in to the CMS are approved automatically. Reply as the practice in plain, friendly words, and never give a diagnosis in a comment.

Edit the footer notes New

  1. Open Manage > Widgets.
  2. Open the Footer notes area. These short notes show above the copyright line on every page.
  3. Edit a widget's title and text, drag to reorder, or add a new one. Keep each note to two short sentences.

Use a reusable section in an article New

  1. Create or edit sections under Manage > Sections. Two exist already: "Insurance we accept" and "New patient offer".
  2. In a post or service body, use Insert Section and pick one.
  3. The section's text is copied into the article. You can adjust it there.

Because it is a copy, editing the section later does not change articles that already use it. Update those by hand.

SEO checklist

Staging is hidden from Google on purpose. Every page sends "noindex". Do not try to change that. It is switched off by a developer at launch on the real domain.

Rules for every page

  • Meta title: the field allows 70 characters. The suffix "| Linden Dental Studio" is added for you, unless the title already names the practice. So keep your part to about 40 characters.
  • Meta description: the field allows 170 characters. Aim for 140 to 160. Say what the page offers and who it is for.
  • One H1: the H1 heading field is the only H1. In article bodies, start at H2.
  • Alt text: every content photo has one. Describe the photo plainly. No keyword lists.
  • Slugs: short, lowercase, words joined by hyphens. Changing a live slug needs a redirect.
  • Share image: 1200 x 630 px works best. Empty means the default family photo is used.
  • Empty fields fall back. No meta title means the page title is used. No description means the summary, then the Site settings default.

Using Claude with an API token

EmDash has a built-in MCP server. Claude Code can connect to it and do CMS work for you: list, read, create and update entries, publish, schedule, view and restore revisions, upload media, edit menus, categories and tags, and read settings. It works with your permissions, so check its work like a colleague's.

1. Create a token

  1. Open Admin > Settings > API Tokens and click Create New Token. (Administrators see this screen.)
  2. Name it after the person and device, for example "Claude, Priya laptop".
  3. Pick the fewest scopes that do the job. For writing posts: Content Read, Content Write, Media Read, Media Write. Add Taxonomies Manage for categories and tags, and Menus Manage only if Claude must edit menus. Do not pick Admin or Schema Write.
  4. Set an expiry: 30 or 90 days. Avoid "No expiry".
  5. Click Create Token and copy it. It is shown once only.

2. Connect Claude Code

Run this once in a terminal, with your token in place of YOUR_TOKEN:

claude mcp add --transport http linden-cms https://stanventures-psi.fly.dev/_emdash/api/mcp --header "Authorization: Bearer YOUR_TOKEN"

Then start Claude Code and type /mcp. You should see linden-cms as connected.

3. Ask in plain words

  • "Add a journal post about whitening myths as a draft. Category Treatments. H2 subheadings, about 600 words, excerpt under 220 characters."
  • "List all journal posts in linden-cms with their status and publish date."
  • "Rewrite the meta description of the Clear aligners service. Keep it under 160 characters. Show me before you save."
  • "Schedule the whitening myths draft for 3 November at 9:00 Portland time."
  • "Show the revisions of the flossing post and tell me what changed last."

Ask for drafts, then read them with Preview and publish yourself.

Keep the token secret.

  • A token acts as you. Anyone who has it can do what you can.
  • Never paste it into a chat, email, ticket, doc or Slack. Never commit it to a code repository.
  • The command above saves it in your Claude Code settings on your computer. Do not share that file.
  • If a token may have leaked, revoke it at once on the API Tokens screen and create a new one.
  • Revoke tokens you no longer use.

Known limits

  • Staging address. The site lives under /linden-dental on staging, while the admin sits at the root (/_emdash/admin). Type internal links without the prefix. Redirect destinations on staging need it.
  • Fields are fixed in code. You cannot add, rename or remove a field from the admin. Ask a developer.
  • New page types need a developer. The seven fixed pages each have one entry. A new kind of page, such as a careers page or a landing page, is built in code first.
  • No history on pages. Pages, Team, Reviews and Site settings have no drafts or revisions.
  • Icons come from a fixed list. A new icon needs a developer.
  • Design changes need a deploy. Colours, fonts, layout and motion are code. Content never needs a deploy.
  • Leave developer screens alone. Content Types, Plugins and Import change how the site is built and can break pages.
  • Concept content. The practice, people and reviews are fictional, and phone numbers use the 555 test range. Replace them before any real launch.
